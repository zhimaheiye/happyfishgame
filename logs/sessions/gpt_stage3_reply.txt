==================================================
二、Gem 配方中也必须区分“游戏事实”和“当前账号状态”
==================================================

你已经观察到配方卡有：

【您已拥有 X 条】

以及材料显示：

have / need

这里必须非常谨慎。

例如：

红宝石 12 / 30

其中：

12 = 当前玩家账号拥有的宝石数量
30 = 这张配方固定要求的数量

Wiki 真正应该保存的是：

required_quantity = 30

而不是：

quantity = 12

也不要把：

“您已拥有 3 条”

写成目标鱼配方属性。

推荐：

canonical recipe:

{
  "target_fish": "...",
  "requirements": [
    {
      "resource_type": "gem",
      "resource_name_raw": "...",
      "required_quantity": 30
    }
  ]
}

如果你认为当前账号数量对排错有价值，
可以单独存在：

observed_account_state: {
  "target_owned_quantity": 3,
  "resources": [
    {
      "resource_name_raw": "...",
      "observed_owned_quantity": 12
    }
  ]
}

或者干脆只保留在截图证据里。

Canonical Wiki 数据绝不能把：

have
与
need

混淆。

同理：

Tab 1 的：

今日已兑换 X/10

其中 X 属于账号/当天状态。

“每日上限 10”如果经过实测证明确实是游戏规则，
才属于公共规则。
