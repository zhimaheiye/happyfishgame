# docs/workflows/atlas-collection.md：游戏图鉴采集工作流

> 本文档沉淀《开心水族箱》游戏内大图鉴（4331 总量）的 UI 结构、交互坐标、全自动化采集流程与异常容错规范。  
> 目的是让任何自动化脚本或新接手 Agent 无需重新摸索 UI 规律。

---

## 一、图鉴 UI 结构与交互特征

### 1. 基础环境与规格
- **分辨率**：固定横屏 `1920 x 1080`。
- **底层引擎**：基于 Cocos2d-x 渲染，无原生 Android 控件树（uiautomator 无法捕获游戏内组件），必须依赖 **ADB 坐标交互 + 截图视觉识别/OCR**。

### 2. 界面层级与入口辨析
1. **千鱼收集**：主界面右侧顶层气泡图标（蓝皮书+星星）打开的是以章节（1/2/3/4/11）为单位的“邮票式集邮活动”，**并非包含 4331 条鱼的全局大图鉴**。
2. **全局大图鉴（4331 Atlas）**：
   - 顶部标有：`收集进度 XX% XXXX/4331`；
   - 顶部包含搜索输入框与【标签查找】按钮；
   - 顶部第 6 个 Tab 为金黄色带星图鉴书图标；
   - 右侧包含纵向快速跳转导航栏：标有 `1`、`100`、`200`、`300`、`400`... 区段锚点。

### 3. 图鉴卡片网格布局（1920x1080 坐标参考）
每屏展示 **2 行 × 6 列**，共 12 个主卡位：
- **行 1 中心纵坐标**：约 `Y ≈ 410`
- **行 2 中心纵坐标**：约 `Y ≈ 700`
- **各列横坐标分布**：
  - Col 1: `X ≈ 230`
  - Col 2: `X ≈ 510`
  - Col 3: `X ≈ 790`
  - Col 4: `X ≈ 1070`
  - Col 5: `X ≈ 1350`
  - Col 6: `X ≈ 1630`
- **右侧区段跳转栏**：`X ≈ 1790`
- **左上角返回按钮**：`X ≈ 90, Y ≈ 65`

### 4. 详情弹窗结构
点击任意鱼卡片（已拥有或未拥有）均会弹出居中半透明水泡详情弹窗：
- **左上方**：鱼动态插画及收藏心标；
- **右上文本区**：
  - 第一行：鱼名（大字，如“小丑鱼”）；
  - 第二行：类别标签（如“真实鱼”）；
  - 第三行：特点描述（如“活泼，好动”）；
- **参数区域**：
  - `产宝时间：` （如 15秒）；
  - `皇冠时间：` （如 60分钟）；
  - `获得来源：` （包含小图标及胶囊按钮/文本，如“商店购买”）；
- **未拥有/未解锁鱼类 UI 特殊语义**：
  若该鱼尚未解锁（`collection_state: "unowned"`），游戏详情页会隐藏“产宝时间”与“皇冠时间”，以横条文字“很遗憾，你还没有解锁这条鱼，喜欢就快去获得吧！”替代。此时 `produce_time_raw: null`, `crown_time_raw: null`，此为游戏预期的稳定 UI 语义，**严禁**误判为 OCR 失败丢入 unresolved。同时，其【获得来源】胶囊按钮始终清晰可见且完全可采。
- **弹窗关闭机制**：点击弹窗外空白区域（如 `X: 960, Y: 150`）或左上角返回，即可关闭详情且**列表滚动位置不会丢失**。

## 二、标准自动化采集闭环流程

```text
[当前图鉴位置]
       │
       ▼
   [定位鱼卡] ────> 点击卡片坐标 (X, Y)
       │
       ▼
  [详情弹窗展现]
       │
       ├────> 1. 截取全屏原始图保存至 raw/screenshots/{filename}.png
       │
       ├────> 2. OCR / 视觉模型提取关键字段:
       │         - name
       │         - category_tag
       │         - description
       │         - produce_time_raw
       │         - crown_time_raw
       │         - acquisition_raw (原文强保留)
       │
       ├────> 3. 标准化转换 (produce_time_seconds, acquisition_type, availability)
       │
       ├────> 4. 追加写盘: data/fish.jsonl
       │
       ├────> 5. 点击遮罩空白区关闭详情弹窗
       │
       ▼
[更新 checkpoint] ───> 写入 checkpoints/progress.json
       │
       ▼
  [推进至下一条]
```

## 三、异常分级与容错规程

必须严格区分“局部数据异常”与“全局执行阻塞”，两者的处理策略截然不同：

### 1. 【局部数据异常】（不挂起主流程）
**典型表现**：
- 单条鱼 OCR 失败或置信度低；
- 单个鱼卡片由于动效或遮挡未点开；
- 一条获取来源文字模糊或缺失。

**处理规程**：
- 绝不挂起整体循环，保持采集的连续性。
- 保存当前证据截图至 `raw/screenshots/unresolved_{index}.png`。
- 向 `unresolved/unresolved.jsonl` 登记问题样本与异常类型（如 `acquisition_text_blur`）。
- 点击空白区域关闭弹窗，推进至下一条卡片。

### 2. 【全局执行阻塞】（立即止损，请求 AI 指导）
**典型表现**：
- 意外离开大图鉴，失去当前视图上下文；
- 无法判断当前处于游戏哪个页面；
- 自动化主循环彻底卡死或无法继续推进；
- 执行自动恢复流程连续 2 次失败。

**处理规程**：
- **停止继续盲目识别与随机点击探索**：禁止在未知界面随意盲点造成更严重的界面偏移或意外购买。
- **存证现场**：保存当前全屏完整截图至 `raw/screenshots/recovery/`。
- **向技术指导汇报**：说明已尝试的操作、当前截图与预期不符之处，向 **ChatGPT** 请求技术恢复路径。
- **关于“停止”的边界定义**：这里的“停止”是停止错误的盲目自动探索，而非无所作为等待人类用户决策。一旦 ChatGPT 给出恢复方案立即自动恢复执行。**只有涉及账号资产、安全风险、不可逆操作或真正的产品方向选择时，才升级到用户本人。**

## 四、意外退出大图鉴后的恢复流程

当检测到当前画面丢失大图鉴特征（非 `STATE_ATLAS_READY`）时，执行以下确定性恢复状态机（最多尝试 2 轮）：

### 1. 恢复路径与实测坐标（1920×1080）

```text
次级页面 / 模态弹窗 / 其他页面
       │
       ▼ [第 0 步] 模态退栈
       │           - 机制：若当前处于次级弹窗（如碎片兑换、配方书）或水族箱子页面，先点击左上角返回 (70, 65) 两次退回主水族箱
       │           - 延迟：每次点击等待 0.8 秒
       │
       ▼ [第 1 步] 点击右下角宝箱气泡
       │           - 视觉描述：主水族箱右下角漂浮的金色敞口藏宝箱（内盛各色宝石金币）
       │           - 实测坐标：X: 1830, Y: 950
       │           - 等待延迟：1.5 秒（等待底部功能气泡行完全弹出）
       │
       ▼ [第 2 步] 从左向右点击第 5 个书形按钮
       │           - 视觉描述：底部展开的功能条中，从左往右数第 5 个气泡（红皮精装书，封面上印有金鱼，带多色书签）
       │           - 实测坐标：X: 1195, Y: 915
       │           - 等待延迟：2.0 秒（等待图鉴分类大面板渲染加载）
       │
       ▼ [第 3 步] 点击顶栏最右侧 Tab 6
       │           - 视觉描述：上方并排 6 个 Tab 选项卡中最右边的一个（第 6 个金色星标图鉴书）
       │           - 实测坐标：X: 1260, Y: 85
       │           - 等待延迟：2.5 秒（等待 4331 大图鉴卡片网格加载完毕）
       │
       ▼ [第 4 步] 强特征严格验证
```

> [!IMPORTANT]
> **坐标与图标描述并存原则**：自动化脚本优先使用实测坐标以达到毫秒级极速跳转，但必须同时保留图标视觉特征描述。若后续游戏 UI 改版或分辨率浮动导致坐标偏移，应通过视觉特征重新对齐坐标。

### 2. 大图鉴成功状态判定（STATE_ATLAS_READY）

必须严格校验以下特征中的多项，确认全部符合后方可认定回到真实大图鉴，严禁“看起来像图鉴”就草率继续：
1. **收集进度**：顶部存在“收集进度”文本；
2. **总量基数**：进度数值基数必须严格为 `/4331`（如 `1052/4331`，区分于分章节的千鱼收集）；
3. **搜索体系**：顶部中央存在白色长条搜索输入框及绿色【搜索】按钮；
4. **标签筛选**：顶部右上存在绿色【标签查找】按钮；
5. **区段导航**：右侧纵向存在 `1` / `100` / `200` / `300` / `400` ... 数字区段快速跳转锚点；
6. **卡片网格**：下方主展示区呈现 2 行 × 6 列的鱼类卡片网格。

满足上述特征后：
- 保存存证截图：`raw/screenshots/recovery/atlas_recovery_success_<timestamp>.png`
- 认定状态：`STATE_ATLAS_READY`
- 从 `checkpoints/progress.json` 记录的上次断点区段继续正常采集。

### 3. 恢复失败止损
- 若执行完 3 步后校验未通过，允许重试执行最多 **1 次**（总计 2 次）。
- 若第 2 次仍未恢复 `STATE_ATLAS_READY`，立即停机，保存实时截图，向 ChatGPT 汇报完整的步骤、实际坐标与现场截图，等待指导。

## 五、已验证的重要工程结论

- **列表状态保持**：从卡片详情弹窗返回后，大图鉴的滚动条与偏移量保持原位，不需要从头重新翻页。
- **未拥有鱼类同样支持详情查看**：无论玩家是否收集该鱼，点击卡片均可调出完整的获取途径与产宝信息，具备完整可采性。
- **右侧导航区段精准有效**：点击 `100`、`200`、`300` 等右侧锚点可迅速对齐大区段，极大缩减滑动翻页误差。
