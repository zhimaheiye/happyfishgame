# docs/playbook/storage-policy.md：存证截图与 Git 仓储体积控制策略

> **起因**：ChatGPT 项目负责人指出，全量 4331 图鉴采集若全数保存 1080P 无损 PNG 并推入 Git 历史，将导致远程仓储急剧膨胀，触发 GitHub 软限制与克隆灾难。  
> **实测数据（2026-09-03）**：
> - 1080P 全屏 PNG（1920x1080）：平均 **740 KB / 张**
> - 裁剪卡片 PNG（Card Crop）：平均 **95 KB / 张**
> - 转换为 WebP（Quality=85）：平均 **85 KB / 张**（压缩率达 88.5%）

---

## 一、容量规模推算

| 存储方案 | 4331 样本预计体积 | Git 友好度 | 评估结论 |
|---|---|---|---|
| **原图 1080P PNG 进 Git** | ~ 3.2 GB | 极差（超出 GitHub 建议的 1GB 上限） | **严禁采纳** |
| **裁剪核心卡片 PNG 进 Git** | ~ 390 MB | 良好（适合作为代码级伴随证据） | **推荐用于配方与核心卡片** |
| **全景图转换为 WebP 进 Git** | ~ 360 MB | 极好（兼顾全屏原貌与轻量化） | **推荐用于阶段性全屏切片** |
| **本地保留无损 PNG + 远端仅同步元数据** | 本地 3.5 GB / Git < 50 MB | 最佳 | **长期生产推荐** |

---

## 二、当前项目执行策略

1. **本地存证绝不删除**：所有 ADB 抓取的无损 1080P 全屏截图一律保存在本地 `raw/screenshots/`，作为不可推翻的最终物理证据链；
2. **Git 提交策略**：
   - 临时调试与中间滑动测试图（如 `test_*.png`、`comp_*.png`）仅保留本地，不强行 stage；
   - 核心配方存证图片（`raw/screenshots/gem_recipes/`）与关键阶段验证图随版本库提交；
   - `data/` 结构化数据、`reports/` 验收报告、`docs/` 专业文档 100% 纳入 Git 管理并持续 Push。
